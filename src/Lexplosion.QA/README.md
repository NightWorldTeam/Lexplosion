# Lexplosion QA — локальная диагностика производительности

Модуль **не отправляет данные в сеть** и **не включён по умолчанию**.

## Как включить

Перед запуском лаунчера установить переменную окружения `LEXPLOSION_QA=1`.
Для PowerShell:

```powershell
$env:LEXPLOSION_QA = "1"
.\Lexplosion.exe
```

После запуска/переключений смотреть:

`%APPDATA%\lexplosion-data\Diagnostics\ui-performance.log`

В лог попадают только заранее заданные имена операций, длительности, UTC-время и ID потока. Никаких URL, имён игроков, токенов и параметров сборок. Запись через ограниченную очередь (не более 512 событий) в фоновом потоке. Файл ротируется после 2 МБ (одна копия `.old`).

## Что смотреть

- `ui.dispatcher.stall`: насколько дольше обычного интервала 100 мс ждал таймер UI-потока; регистрируется при задержке сверх нормы более 150 мс. Не является точным FPS/GPU-трекером.
- `navigation.sidebar.<ViewModelType>`, `navigation.tabs.<ViewModelType>`, `navigation.page.<ViewModelType>`: момент начала смены страницы и тип ViewModel (только имена .NET-типов, не пользовательские данные).
- `navigation.sidebar.commit`: время применения выбранного ViewModel в боковом меню.
- `navigation.tabs.commit`: время подключения выбранного содержимого вкладки.
- `navigation.page.prepare`: время между постановкой нового содержимого и началом WPF-перехода после layout.
- `collection.filter.rebuild`: перестроение фильтрованной коллекции на UI-потоке дольше 20 мс.

## QA-сценарий

1. Включить переменную окружения и запустить лаунчер.
2. По 10–20 раз переключить «Каталог ↔ Библиотека ↔ Настройки», включая быстрое переключение.
3. Открыть профиль сборки и переключить «Обзор ↔ Дополнения» и внутренние вкладки.
4. Повторить при отключённых анимациях в настройках.
5. Проверить лог на `ui.dispatcher.stall` и сопоставить временные метки с `navigation.*`.

Измерение показывает *где и когда* UI-поток блокируется. Детальное профилирование CPU/памяти дальше выполняется через Visual Studio Profiler / PerfView. Исключения и персональные данные специально не записываются.

## E2E: отдельный проект Lexplosion.E2E

Нагрузочные UI-тесты живут в `src/Lexplosion.E2E`, используют FlaUI.UIA3 и
NUnit на `net48`. Обычные unit-тесты (`Lexplosion.Tests`) остаются на `net472`
и не тянут FlaUI. Приложение и `Lexplosion.Core` менять на net48 не требуется.

### Запуск на Windows

Нужен интерактивный разблокированный рабочий стол и сохранённая авторизация.

~~~powershell
$env:LEXPLOSION_E2E = "1"
dotnet test src/Lexplosion.E2E/Lexplosion.E2E.csproj -c Debug --logger 'console;verbosity=detailed'
~~~

Тест может самостоятельно запустить собранный EXE и включает QA-лог.
При подключении к уже работающему лаунчеру процесс не закрывается;
для performance log в таком режиме запустите лаунчер с `LEXPLOSION_QA=1`.
При желании путь до exe задаётся `LEXPLOSION_E2E_EXE`.

### Сценарии

- `InventoryAllVisibleControlsAndNavigation`: полный инвентарь доступных
  кнопок, переключателей, ссылок и вкладок без опасных кликов.
- `Normal`: все видимые боковые пункты, затем все доступные группы вкладок,
  включая появляющиеся вложенные группы.
- `Reverse`: обратный порядок, проверка состояния последней страницы.
- `Shuffle`: порядок перемешан с фиксированным seed (для воспроизводимости).
- `RapidSwitchingPreservesTheFinalSelection`: серии быстрых кликов без пауз
  и проверка последнего выбранного пункта после завершения обработки UI.
- `OpenReachableInstanceAndServerProfiles`: безопасное открытие профилей
  из библиотеки, каталога и списка серверов, проход доступных вложенных вкладок
  и возврат. При отсутствии карточек маршрут отмечается SKIP.
- `DispatcherPerformanceDoesNotExceedQaBudget`: проверяет наличие QA-лога
  и ошибку, если максимальная задержка Dispatcher выше 700 мс
  (настраивается через `LEXPLOSION_E2E_MAX_STALL_MS`).
- Действия установки, запуска игры, удаления, авторизации и оплаты
  **никогда** не вызываются автоматически.
- Разделы, до которых нельзя добраться без тестовых сборок/серверов/аккаунта,
  отмечаются как **NOT COVERED/SKIP**, а не как PASS.

После анализа прогона 28.10.2026:
- Тест бюджета производительности выполняется **последним** (после всех
  основных маршрутов), а не в начале. Иначе ранний PASS был ложным.
- Время `navigation.sidebar` / `navigation.tab` включает вызов FlaUI и
  подтверждение выбранного состояния, но **не включает** обход всего дерева
  UI Automation и искусственную паузу стабилизации анимации.
- Полная инспекция доступности запускается только в обычном режиме;
  стрессовые сценарии не выполняют тяжёлый UIA-обход после каждого клика.
- Для снимков окно поднимается на передний план, затем проверяется
  стабильность его размеров. Скриншот всё равно нельзя автоматически
  считать доказательством корректной верстки без сравнения с эталоном.

### Функциональные и визуальные проверки

После навигации FlaUI проверяет выбор RadioButton/TabItem, доступность
главного окна, ненулевые размеры и наличие доступных UI-элементов.
После обычных переходов снимает скриншоты для визуальной проверки.
Это не заменяет проверку корректности текста и расположения конкретной страницы.

При необходимости включается сравнение со снимками-эталонами:

~~~powershell
$env:LEXPLOSION_E2E_BASELINES = "D:\\Lexplosion-E2E-Baselines"
$env:LEXPLOSION_E2E_RECORD_BASELINES = "1" # только при подготовке эталонов
~~~

После создания эталонов уберите `LEXPLOSION_E2E_RECORD_BASELINES`.
Скриншоты сравниваются с допуском 5% отличающихся точек.
Для обязательного наличия эталонов установите `LEXPLOSION_E2E_STRICT_VISUAL=1`.
Эталонные проверки требуют фиксированных DPI, размеров окна, темы и
стабильных тестовых данных. Без эталона результат обозначается **UNVERIFIED**.

### Результаты и производительность

Файлы создаются в `%APPDATA%\lexplosion-data\Diagnostics\E2E\<run-id>`:

- `navigation.tsv`: все действия, время и статус PASS/FAIL/SKIP.
- `coverage-summary.txt`: пройденные/непокрытые группы вкладок.
- `ui-performance.log`: копия записей **только текущего E2E запуска**,
  прочитанная из `%APPDATA%\lexplosion-data\Diagnostics\ui-performance.log`.
- `performance-summary.txt`: число зависаний Dispatcher, max/p95 в мс,
  статистика подготовки страниц и отметка наличия телеметрии.
- `visual-results.tsv`: PASS/FAIL/UNVERIFIED для сравнений скриншотов.
- `*.png`: снимки после обычной навигации и снимок при ошибке.

Navigation, coverage и performance файлы прикрепляются к NUnit TestContext,
а путь каталога печатается в выводе тестов.
Снимки могут содержать пользовательские данные — проверяйте перед отправкой.

### Ограничения

UIA-тесты нельзя запускать в обычной безэкранной Windows-сессии CI.
Пока нет специально подготовленных профилей и безопасной автоматизации
открытия карточек, E2E не гарантирует посещение профиля каждой сборки,
сервера, модального окна и элементов виртуализованных списков.
Повторный проход по каждой открытой странице не гарантирует правильную
отрисовку без эталонов и семантических проверок её конкретного содержимого.
